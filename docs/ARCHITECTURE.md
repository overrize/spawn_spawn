## 1 · 组件清单

| 组件 | Tier | 数量 | 模型 | 生命周期 |
|---|---|---|---|---|
| **Leader** | 0 (root) | 1 | claude-sonnet-4-6 (Pro) | 持久 |
| **Leader Secretary** | 0-sat | 1 | claude-haiku-4-5 (Flash) | 持久 |
| **Dev Manager** | 0-peer | 1 (可选) | claude-sonnet-4-6 | 按需 |
| **Process Manager** | meta | 1 (树外) | claude-haiku-4-5 | 持久，只读 |
| **SpawnUnit** | 1..N | 多个，树形 | 按技能配置 | 任务作用域或持久 |
| **SpawnUnit Secretary** | SpawnUnit 的伴侣 | 每个 SpawnUnit 1个 | claude-haiku-4-5 | 与父节点同生命周期 |

**配对规则（强制）**：每个 SpawnUnit 创建时必须同时创建 Secretary，作为原子 SpawnPair。SpawnUnit 终止时级联终止 Secretary。存活的 SpawnUnit 若 Secretary 已终止，PM 触发 `orphaned_unit` 告警。

## 2 · Spawn 树拓扑

### 2.1 形状

```
               Process Manager (meta, 只读订阅事件流)
                        │
                        ▼
            ┌──────────────────────┐
            │   Leader (T0)        │── Leader Secretary (sat)
            │   持有 SkillRegistry  │── Dev Manager (peer, 可选)
            └──────────┬───────────┘
                       │ spawn()
         ┌─────────────┼─────────────┐
         ▼             ▼             ▼
    SpawnUnit A   SpawnUnit B   SpawnUnit C
    + Secretary A + Secretary B + Secretary C
         │
         │ spawn()   ← 允许递归
         ▼
    SpawnUnit A.1
    + Secretary A.1
```

### 2.2 Fork / Join

- `parent.spawn(spec)` 非阻塞，父节点继续运行
- `child.handUp(result)` 发出 `unit.handup` 事件，父节点通过事件订阅接收
- Join 是**显式**的，没有自动阻塞
- 自终止：child 发出 `agent.done`，Secretary 写入最终内存快照，然后双方退出

### 2.3 深度限制

- 最大自主深度：**3**（Leader=0, 子=1, 孙=2, 曾孙=3）
- 超过 3 层需要 Leader 颁发 `parentApprovalToken`
- 违反时返回 `agent.error.code = "depth_exceeded"`
- 每个 SpawnUnit 最大同时子节点：**4**（PM 监控，不阻止）

## 3 · Skills 系统

### 3.1 Schema（JSON 文件）

Skills 存放在 `~/.config/multi-agent-tui/skills/<name>.skill.json`：

```json
{
  "name": "code-reviewer",
  "version": "1.2.0",
  "description": "Reviews diffs for correctness, style, and security.",
  "domain": ["typescript", "react", "node"],
  "tools": {
    "allow": ["Read", "Grep", "Glob", "Bash(git diff:*)", "Bash(git log:*)"],
    "deny":  ["Bash(rm:*)", "Bash(git push:*)", "Write", "Edit"]
  },
  "mcp_servers": [
    { "name": "github", "url": "stdio:gh-mcp", "required": false }
  ],
  "model_hint": "claude-sonnet-4-6",
  "max_turns": 25,
  "memory_quota_kb": 32,
  "system_prompt_fragment": "./fragments/code-reviewer.md",
  "inheritable": true,
  "min_depth": 0,
  "max_depth": 3
}
```

字段语义：
- `tools.allow/deny`：传给 `claude --allowed-tools` / `--disallowed-tools`，deny 优先
- `inheritable: false`：特权 skill（如 git-push），子节点不能继承
- `min_depth/max_depth`：限制哪个 Tier 可用（如 sdk-compile 的 `min_depth: 1`）
- `memory_quota_kb`：Secretary 执行，超限时 PM 告警

### 3.2 合并规则

- `tools.allow`：union；`tools.deny`：union（任意 deny 胜）
- `model_hint`：最高优先级 skill 胜出
- `system_prompt_fragment`：按加载顺序拼接在 `## Skills` 标题下

### 3.3 继承规则（父 → 子）

1. 默认：child 继承 parent 中 `inheritable === true` 且 depth 在范围内的所有 skill
2. 限制：spec 可传 `skills.exclude: [name…]` 进一步剔除
3. 请求额外：spec 可传 `skills.request: [name…]`，需 Leader registry 中有该 skill
4. 禁止向上升权：child 不能授予自己 parent 没有的 skill，PM 告警

## 4 · Memory Schema

每个 agent 持久化一个 Memory 文件：`./.spawn/memory/<agent_id>.json`

```json
{
  "schema_version": 1,
  "agent_id": "spawn-7a3e2b91",
  "agent_type": "SPAWN",
  "parent_chain": ["main-1f2a3b4c", "spawn-2d3e4f5a"],
  "depth": 2,
  "created_at": 1731580020000,
  "updated_at": 1731583021000,

  "identity": {
    "role_name": "code-reviewer",
    "skills": ["code-reviewer", "git-readonly"],
    "model": "claude-sonnet-4-6"
  },

  "dispatch": {
    "background": "用户需要对 Login 表单进行安全审计。",
    "constraints": ["不写文件", "20 轮内结束"],
    "acceptance_criteria": ["列出所有 XSS 入口", "引用行号"],
    "stop_conditions": ["agent.done", "30min 墙钟", "连续 3 次读取无发现"]
  },

  "working_set": {
    "facts":     [ { "id":"f1", "text":"…", "src":"src/Login.tsx:42", "ts": 0 } ],
    "decisions": [ { "id":"d1", "text":"…", "rationale":"…", "ts": 0 } ],
    "open_questions": [ { "id":"q1", "text":"…", "blocking": true } ]
  },

  "child_handles": [
    { "agent_id":"spawn-9b2c…", "status":"running", "goal":"…", "handup": null }
  ],

  "tombstone": {
    "compact_summary": null,
    "final_status": null,
    "final_artifacts": [],
    "resume_hint": null
  },

  "self_optimization": {
    "proposals": [
      { "id":"p1", "ts": 0, "target":"role_boundary", "diff":"…", "status":"pending_review" }
    ]
  }
}
```

**必填字段**（Secretary 写入前验证）：`schema_version`, `agent_id`, `agent_type`, `parent_chain`, `depth`, `created_at`, `updated_at`, `identity`, `dispatch`（4 个子字段必须存在，可为空数组），`tombstone`（shutdown 前为 null）。

**存储**：`./.spawn/memory/` 纳入 git 管理。高频临时数据写入 `.spawn/memory/<id>.scratch.json`，加入 `.gitignore`。

## 5 · Memory 继承规则

### 5.1 spawn() 时向下传递

child Memory 文件在 spawn 时创建，以下字段从 parent 填充：

| 字段 | 来源 |
|---|---|
| `parent_chain` | parent 的 chain + parent.id |
| `identity.skills` | 按 §3.3 过滤后的技能列表 |
| `dispatch.background` | spec.background（必填） |
| `dispatch.constraints` | parent 的 + spec 的（叠加） |
| `working_set.facts[*]` 中 `inheritable_tag === true` 的 | parent 的选择性事实 |

**不传递**：parent 的 decisions、open_questions、tombstone 历史、兄弟节点内存。

### 5.2 handUp() 时向上汇报

```json
{ "summary": "≤300字", "artifacts": [...],
  "facts_to_promote": ["f3","f7"], "decisions": ["d1"], "failed_acceptance": [] }
```

parent Secretary 消化：把 summary 追加到 parent `working_set.facts`（src = `handup:<child_id>`），复制被提升的 facts/decisions。child Memory 文件保留，直到 parent 终止。

### 5.3 Secretary 垃圾回收

每 5 轮或 pre-shutdown 触发，只处理自己配对的 SpawnUnit 的 Memory：

1. 去重 `working_set.facts`（语义哈希）
2. 超过 100 轮且无引用的 facts → 移到 `archive` 子键
3. 大小 > 80% quota 时：按 tag 聚类 facts，每簇压缩成一条摘要 fact
4. `blocking:false` 且超 50 轮的 open_questions → 删除

Leader Secretary 额外每分钟做一次跨节点 pass：读所有 child tombstones，合并提升的 facts 到 Leader working_set。

**Secretary 不可修改**：`dispatch`、`identity`、`self_optimization`（这三个字段只有 Leader 可改）。

## 6 · Process Manager 监控规则

PM 订阅同一条 TuiEvent 流（只读），运行在独立子进程中，发出 `pm.alert` 事件：

```json
{ "v":1, "type":"pm.alert", "severity":"warn|error",
  "code":"<rule_id>", "agent":"<id>", "detail":"…", "ts":0 }
```

### 6.1 规则清单

| Rule ID | 触发条件 | 严重度 |
|---|---|---|
| `dispatch_missing_background` | spawn 事件 spec 缺少 background | error |
| `dispatch_missing_acceptance` | spawn spec 的 acceptance_criteria 为空或缺失 | error |
| `dispatch_missing_stopcond` | spawn spec 缺少 stop_conditions | error |
| `dispatch_missing_constraints` | spawn spec 缺少 constraints 键 | warn |
| `runtime_exceeded` | agent RUNNING 超 30min 无 agent.done | warn |
| `runtime_exceeded_hard` | 超 60min | error |
| `no_progress` | RUNNING 状态超 5min 无 step/todo 事件 | warn |
| `memory_not_saved` | TERMINATED 前无 memory.snapshot 事件 | error |
| `tombstone_missing` | terminated agent 的 tombstone.compact_summary 为 null 超 30s | error |
| `orphaned_unit` | SpawnUnit 存活但 Secretary 已 TERMINATED/ERROR | error |
| `fanout_exceeded` | parent 有 >4 个 RUNNING 子节点 | warn |
| `depth_exceeded_attempt` | spawn 被 depth_exceeded 拒绝 | warn |
| `skill_escalation` | child 请求了 parent 没有的 skill | error |
| `protocol_violation_rate` | 60s 内 parser-error 事件 >5 个 | warn |
| `cost_burn` | 5min 内 cost_usd 增量 >$5 | warn |
| `quota_exceeded` | memory 文件超 quota 且经历 >2 次 GC | warn |
| `loop_suspected` | 100 个事件内同一 tool.call.args.path 出现 >10 次 | warn |

### 6.2 非干预保证

PM 没有 `sendCommand` 能力。只能读，不能杀、暂停、发消息给 agent。告警显示在 TUI 的 PM 告警栏，由用户决定是否处理。

## 7 · 自优化循环

### 7.1 可提案修改的文件

每个 agent 两个文件（路径：`.spawn/identity/<agent_id>/`）：
- `role_boundary.md`：这个角色做什么/不做什么
- `principles.md`：历史经验形成的启发式规则

这两个文件在 `_base.md` 和 `<role>.md` 之后注入系统提示。**基础 prompt 不可被 agent 修改**。

### 7.2 循环流程

```
Agent 工作中 ──提案──▶ memory.self_optimization.proposals[]
     │
     │ agent.done 或每 20 轮，Secretary 将新提案提升到
     │ ./.spawn/proposals/<agent_id>/<proposal_id>.json
     ▼
Leader 审查队列（TUI 显示待审计数）
     │
     │ Leader 用 /review-proposal <id> → 读 diff → 决定
     ▼
应用：Leader 修改 role_boundary.md / principles.md（git commit）
      → agent 下次重启时加载新提示
拒绝：提案标记 rejected + 原因，保留在 proposals/ 作审计
```

### 7.3 防漂移机制

1. identity 文件 git 追踪，每次变更有 commit
2. PM 规则 `principle_explosion`：principles.md 超过 50 条 bullet → 告警（强制压缩）
3. PM 规则 `drift_review_due`：每 30 天提醒 Leader 与 `prompts/<role>.md` 基线对比
4. 提案必须是 unified diff，不允许全文重写
5. 提案 agent 不能自己应用，必须 Leader 审核

## 8 · 启动/关闭协议

### 8.1 关闭流程（每个 agent）

```
1. Agent 收到关闭信号
2. Agent 发出 shutdown.start 事件
3. Secretary:
   a. 对话 compact → 写入 tombstone.compact_summary, final_status, final_artifacts
   b. 写 tombstone.resume_hint = "上次在做：<step>。下一步：<todo>。"
   c. 最终 GC
   d. 发出 memory.snapshot 事件（含路径和大小）
4. Parent Secretary 将 child tombstone 路径写入 parent.child_handles[i]
5. Agent 进程退出
6. Secretary 进程在 parent 确认 memory.snapshot 后退出
```

### 8.2 启动恢复流程

```
1. TUI 扫描 .spawn/memory/ 找到 main-*.json
2. 启动 Leader 子进程，--resume <leader.session_id>，注入 RESUMING 提示
3. Leader 读自己的 Memory 文件：identity, dispatch, tombstone, child_handles
4. Leader 对每个 child_handle 决策：重启、重新分配、关闭
5. 每个需要恢复的 child：--resume <child.session_id>，读 tombstone.resume_hint
6. Secretary 配对重启，读同一 Memory 文件
7. PM 最后启动，订阅事件流（无需 resume）
```

### 8.3 崩溃恢复

- Memory 文件反映最后一次 git commit 状态（Secretary 写入立即 fsync）
- tombstone.compact_summary 为 null 的 child → PM 告警 → Leader 决策：重启（丢失上下文，但状态已知）或标记为 `closed_orphan`

## 9 · DispatchSpec（形式化 Schema）

每个 `spawn()` 调用必须携带此对象，Leader 在 spawn 前验证，PM 在 spawn 后验证：

```typescript
interface DispatchSpec {
  child_id?: string;
  role_name: string;
  model?: string;

  // 4 个必填字段
  background: string;
  constraints: string[];
  acceptance_criteria: string[];   // 至少 1 条
  stop_conditions: string[];       // 至少 1 条

  skills: {
    inherit_default: boolean;
    exclude?: string[];
    request?: string[];
  };

  max_turns?: number;
  memory_quota_kb?: number;
  seed_facts?: string[];
}
```

拒绝原因（`agent.error.code`）：`dispatch_invalid`, `skill_not_found`, `depth_exceeded`, `fanout_exceeded`, `skill_escalation`。

## 12 · 待用户决策的开放问题

1. **Secretary 模型替代方案**：纯 DeepSeek 部署时 Secretary 用什么？选项：(a) 强制 Claude, (b) DeepSeek with 严格 parser, (c) Secretary 逻辑写成 TypeScript（不用 LLM）
2. **递归深度默认值**：设计取 3，"公司层级"类比可以是 4（CEO→VP→Manager→IC）
3. **Memory 文件位置**：项目内 `.spawn/memory/`（污染项目仓库）vs `~/.local/share/`（不在项目 git 中）
4. **PM 实现方式**：Haiku LLM agent vs 纯 TypeScript 规则引擎（热规则是机械的，推荐规则引擎 + LLM 只做模糊规则）
5. **自优化应用机制**：相关 SpawnUnit 是否需要重启才能加载新 prompt？yes=实现简单，no=需要热重载
6. **Skill 在线创作**：Leader 能否在会话中途写新 `.skill.json`？yes=需额外 PM 规则
7. **跨节点内存可见性**：兄弟节点能否写公共 scratch？yes=协作能力↑, collision↑
8. **Tombstone 保留期限**：永久（推荐，存储成本低，审计价值高）vs N 次成功恢复后清理
9. **PM 的 runtime_exceeded_hard 权限**：纯信息 vs 弹出一键确认的 kill 建议（推荐后者）
10. **dispatch 强制时机**：spawn() 时同步硬拒绝 vs spawn 后 PM 告警（推荐硬拒绝，fail-fast）
